背景及问题

抓大猪迷你游戏现有操作方式及其引发的冲突问题

🎮 游戏玩法说明

「抓大猪」是将锅内同种类食材3个凑齐后消除的迷你游戏。玩家通过实际摇晃手机来搅动锅内食材，改变食材位置，从而完成消除目标。

⚠️ 当前问题
  • KakaoPay 应用本身具备「摇晃支付」功能
  • 玩家在抓大猪游戏中摇晃手机时，KakaoPay 的摇晃支付也会被同时触发
  • 导致游戏被强制退出，且重新进入后扣除游戏次数
💡 解决方案方向

需要移除设备摇晃操作，将原有的「搅动食材」功能替换为游戏内的屏幕滑动手势，从根本上避免与 KakaoPay 摇晃支付功能的冲突。

2

改善方向

以屏幕滑动替代摇晃，保留核心游戏体验

1
完全移除实际摇晃设备的动作 → 阻断与 KakaoPay「摇晃支付」功能的冲突
2
在锅和食材槽以外的屏幕区域，用手指滑动即可触发食材搅动效果
3
为与「锅上方拖拽（食材轮廓确认功能）」区分，模式首次进入时在锅下方显示引导 UI 和说明文案
3

摇晃操作变更前 / 后对比

核心操作方式与交互结果的直观对比

❌ 变更前（AS-IS）
  • 通过实际摇晃手机搅动食材
  • 与 KakaoPay 摇晃支付功能冲突
  • 存在游戏强制退出、次数被扣的风险
✅ 变更后（TO-BE）
  • 通过屏幕滑动手势搅动食材
  • 完全避免与 KakaoPay 功能冲突
  • 交互更可控，体验更稳定

※ 核心要点

滑动操作后，底部被遮挡的食材会向上露出。需以屏幕操作复现与原有摇晃操作完全相同的结果，确保游戏逻辑与体验不变。

5

详细动作定义

触发、表现与结果逻辑的完整说明

Action Trigger
操作触发

在屏幕（锅和食材槽除外）上检测手指滑动手势，识别为「搅动食材」指令。

Visual Effect
表现效果

根据滑动方向与力度，锅内的食材产生相应移动动画，模拟真实摇晃效果。

Result Logic
结果逻辑

直接复用原有摇晃功能的「食材排列重构」逻辑，仅替换触发方式，食材重排算法本身不做变更。
